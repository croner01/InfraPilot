# InfraPilot 前端更新说明

> 更新日期：2026-09-28
> 范围：`web/` 前端全部改造内容，含少量配套后端端点说明（用于标注数据来源与待接入项）。

本轮前端改造围绕四个目标：**专业化 UI（Cortex/Kimi 风格）**、**多数据源接入**、**Agent 标准能力补齐**（Skill 市场/自主生成、用量统计、用户隔离）、**诊断会话全程可视可交互**。所有新页面均标注了后端接入点，mock 数据结构与规划的后端接口同构，后端落地后即插即用。

---

## 一、导航与整体框架

- **侧边栏（`console/SideNav.tsx`）**：
  - 工作区：告警中心 / 诊断会话 / **数据源**（新增）
  - 资源：知识库 / 服务拓扑 / 技能管理 / **用量统计**（新增）/ 系统设置
  - 会话列表（会话视图内嵌）：折叠按钮 `«`、执行中会话脉冲圆点、hover 浮现 ✎ 重命名 / ✕ 删除；折叠后显示「☰ 会话列表」恢复按钮
- **顶栏（`console/TopBar.tsx`）**：新增用户菜单（头像 / 角色徽章 / 审批权限提示 / 退出登录）
- **登录门禁（`LoginPage.tsx`，新增）**：
  - 演示模式：任意密码可登录，可切换 admin（管理员）/ on-call（值班 SRE）/ viewer（只读观察）三种角色
  - 用户态存于 `localStorage`（`infrapilot.currentUser`），未登录全站拦截
  - **RBAC 前端演示**：viewer 角色点击审批会被拦截提示
  - 后端接入点：`/api/auth/login` + JWT，users 表与行级隔离（sessions / audit / approvals / alerts 按 `user_id` 过滤）

## 二、数据源工作台（新页面）

文件：`components/DataSourcesPage.tsx` + `datasources.css`，侧边栏「数据源」入口。

- **概览统计卡**：指标 / 日志 / 数据库 / 知识库各类后端启用数
- **指标查询**：PromQL 编辑器（Ctrl+Enter 执行）、时间范围预设（15m/1h/6h/24h）、常用查询快捷 chips、查询历史、uPlot 曲线图、当前值表格
- **日志检索**：namespace / 级别 / 时间窗 / 关键字过滤，结果表带级别彩色标签
- **SQL 查询**：数据源选择、只读保护徽章、结果表格；顶部**数据源支持矩阵**说明卡（MariaDB=MySQL 协议兼容；ClickHouse/ES 标注「驱动待接入」）
- **知识库**：案例搜索 + 相似度展示，卡片化呈现根因与解决方案

配套（后端，已实现；对应 py-server 模块，原 Node 后端已删除）：
- `py-server/infrapilot/routes/datasources.py`：Prom 瞬时/区间查询代理、label values、连接测试、数据库只读查询
- `py-server/infrapilot/routes/config.py`：指标/数据库数据源 CRUD + 测试
- `py-server/infrapilot/skills/prom.py`：`prom__instant_query / range_query / label_values` 只读 Agent 工具，已注册进 Policy Engine 与 Command Gateway

## 三、诊断会话（Cortex 风格改造）

### 3.1 对话流

- `conversation/Conversation.tsx`：按 `toolCallId` 合并 `tool_call_start/result` 为单张工具卡；**连续 ≥2 张已完成只读调用自动合并为「批量采集」组卡**（显示次数/技能/总耗时，组内卡片独立展开）
- `conversation/ProcessSection.tsx`：Cortex 风格工具卡——状态徽章（执行中/成功/失败）、耗时、入参与结果默认折叠、深色代码块展开查看（超长自动截断）
- `App.tsx` 审批卡：显示 `call_id`、变更 diff 预览、三个按钮 **拒绝 / 批准执行 / 始终允许**
  - 「始终允许」为前端占位：将会话级白名单存于本地并提示，待后端 Policy Engine 实现 `skill+tool` 粒度的会话白名单接口

### 3.2 执行追踪面板（新组件）

文件：`conversation/ExecutionTrackPanel.tsx` + `execution-track.css`，位于右侧面板「执行追踪」Tab。

- **里程碑时间线**：由真实事件流推导——现象确认 → 制定计划 → 证据采集 → 审批与修复 → 结论归档（映射 `user_message / plan_update / tool_call_result / approval_decision / rca_conclusion`）
- **思考实时流**：`assistant_delta` 尾部内容 + 闪烁光标
- **技能调用列表**：含耗时、风险徽章、失败计数、总耗时汇总
- **审计 Tab**：按时间的调用记录（时间 / 风险 / 参数项数）
- 右侧面板本身支持折叠（`»` 按钮）

## 四、告警中心（对齐"告警即诊断入口"设计）

文件：`components/alerts/AlertCenter.tsx`、`AlertList.tsx`。

- **统计卡行**：P0 待处理 / 待处理 / 诊断中 / 已确认 / 已解决 / 累计，随筛选联动
- **筛选工具栏**：状态 Tab（带数量角标）、来源下拉（Alertmanager / 日志规则 / 主动巡检 / 手动）、级别下拉、关键字搜索；来源类型缺失时从 `source` 字符串智能推断
- **告警行增强**：级别 + 来源双徽章、触发次数 `×N`（防抖合并语义）、行展开详情（原始 labels / annotations / 确认与解决时间线 / fingerprint / 关联会话）
- **状态操作**：确认 / 解决（本地乐观更新，后端 PATCH 待接入）/ **一键开查**
- **一键开查真实联动**（复用现有 API）：以 `诊断: <标题>` 创建会话 → `sendMessage` 注入结构化告警上下文（级别/服务/来源/触发次数/标签/描述 + 诊断指令）→ 自动跳转会话视图
- 数据模型扩展（`lib/types.ts`）：`Alert` 新增可选字段 `sourceType / fingerprint / labels / annotations / count / ackAt / resolvedAt`，状态新增 `diagnosing`
- 后端接入点：Alertmanager webhook 入口、`PATCH /api/alerts/:id`、字段扩展（详见差距分析文档 P1）

## 五、技能中心（4 个 Tab）

文件：`components/SkillsPage.tsx`。

- **技能市场**：开源生态卡片（anthropics/skills 的 pdf/docx/xlsx/pptx、openai/skills 等），点击自动填入安装表单；安装流程分步提示（克隆 → 校验 → 复制 → 刷新注册表）
- **已安装技能**：启停 / 卸载（原有能力）
- **Skill Factory（自主生成）**：三步向导——选择历史诊断会话 → 生成 SKILL.md 预览（可编辑）→ 提交审核入库；预览含完整 playbook 示例
- **流程图生成**：原 draw.io 能力

- 「自动发现」按钮带扫描动画（聚合 K8s API）
- SVG 分层拓扑：入口层 → 业务服务 → OpenStack 组件（ironic / nova，标注 `cloud_name=云贯标`）→ 数据层；贝塞尔调用边，错误链路红色虚线流动动画

## 七、用量统计（Token / 成本，新页面）
